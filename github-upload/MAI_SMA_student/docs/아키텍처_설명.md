# 아키텍처 설명 — MAI SMA 학생 패키지

그림 두 장은 연구 시스템(시연판)을 그린 것이다. 이 패키지의 구조와 흐름은 같고, 아래 표의 값이 다르다
(그림 속 수치·이름 가운데 이 표에 있는 것은 이 표의 오른쪽 값으로 읽는다).

| | 그림(연구 시연판) | 이 패키지(학생판 v2) |
|---|---|---|
| 데이터 | 정비이력 DB 6개 테이블(문서 26,561 · 작업 라인 51,715 …, 약 17만 행) | 학생용 DB `data/MAI_SMA_학생용DB_1000.duckdb` — 정비 문서 1,000건(6개 테이블 6,741행) + 질의응답 200문항 |
| 데이터 사전 | 121컬럼 | 123컬럼(연구의 121 + 16자리 복합코드 EQUIP_TAG 2열). 적힌 개수·분포는 전체 선대(17만 행) 기준 |
| 검색 색인 | 서술 300자 이상 19,990건 | 1,046건 = 정비 문서 기록 741(같은 조건) + 참고 기록 305(qa_proc_context) |
| 출처 조회 | master · pms | 정비 문서 기록은 master · pms, 참고 기록은 qa_proc_context(4절) |
| LLM | llama-server(Gemma-4 12B Q4_K_M) 127.0.0.1:50081 | config.json 에 적은 실행기(Ollama · LM Studio · llama.cpp · OpenAI 호환) |
| 화면 주소 | 127.0.0.1:8760 | 127.0.0.1:8780(config.json 의 web_port) |
| 켜기·끄기 | START_DEMO.bat · STOP_DEMO.bat | START.bat · STOP.bat(macOS·Linux: start.sh) — 그 폴더의 서버만 끈다 |

## 1. 계층

![질의 처리 구조](fig_query_architecture.png)

1. **표현 계층** — 브라우저 화면 `app/maintqa_web.html`. 질문 입력 · 대기열 · 단계별 진행과 시간 · 중단 · 한국어 병기 ·
   SQL · 인용 · 출처 표 · 설정 창. 대화는 브라우저에 저장된다.
2. **응용 계층** — 파이썬 HTTP 서버 `app/maintqa_web.py`(127.0.0.1 에서만 듣는다).
   후속 질문 해석 → 규칙 라우터(`app/router.py`, LLM 호출 없음) → 집계형 경로 또는 절차형 경로.
3. **데이터 계층** — 웹 서버 프로세스 안, 읽기 전용.
   DuckDB(`data/…duckdb`) · BM25 검색 색인(`data/bm25_1000.pkl`) · 데이터 사전(`data/datadict_deid.txt`, 123컬럼 = 연구의 121 + EQUIP_TAG 2) ·
   규칙문 12 · 퓨샷 6(`app/build_prompt100.py`) · 설비 용어 대응표 82항목(`app/term_map.py`).
4. **추론 계층** — 학생 PC 의 LLM 실행기. 웹 서버는 OpenAI 호환 `POST {base_url}/chat/completions` 하나만 쓴다
   (`app/llm_client.py`). 요청은 temperature 0 · seed 42, 실행기가 받으면 top_k 1 · 사고 끄기(preset 별로 다르다).

## 2. 집계형 경로(Text-to-SQL)

1. 프롬프트 조립 — DuckDB 카탈로그에서 읽은 DDL(6개 데이터 테이블) + 컬럼 설명 123(연구의 121 + EQUIP_TAG 2) + 규칙문 12 + 퓨샷 6 + 질문 = 조건 F
   (`prompts/01_…`, `eval/prompts/cond_F.txt` 와 글자까지 같다).
2. SQL 생성(LLM, 최대 600토큰) — 코드펜스·사고 덩어리를 걷어 내고 첫 SELECT/WITH 부터 첫 `;` 까지.
3. 기권 판정 — 출력이 `NO_RELIABLE_VALUE` · `NOT_RECORDED` 면 SQL 을 실행하지 않고 사유를 보인다.
4. SQL 실행 — 요청마다 새 커서, 읽기 전용 · 외부 파일·네트워크 접근 차단 · 시간 제한(기본 60초). 오류면 방언을 고쳐 한 번 더.
5. 답 문장 — 수치는 DB 결과 그대로(모델을 거치지 않는다, `app/answer_text.py`). 표와 실행한 SQL, 읽은 테이블·컬럼을 함께 보인다.

모델에게 보이는 테이블은 6개(master · pms · consumption · attachments · approval · vessels)뿐이다. 학생용 DB 의 `qa_*` 표와
`prompt_templates` 는 DDL 에 넣지 않는다.

## 3. 절차형 경로(검색 + 인용 검증)

1. 용어 대응 — 질문 속 설비 이름(한·영)을 기록이 쓰는 표기로(대응표 82항목).
2. 질문 번역(LLM) — 한국어 질문일 때만 영어로. 기록 본문과 색인이 영어라서다.
3. BM25 검색 — 번역문에 기록 표기를 덧붙여 상위 4건. 결과가 없으면 끝.
4. 문맥 조립 — 기록 4건(제목 · 기기 · 장비 · 날짜 · 본문) + 같은 설비의 다른 이름 안내.
5. 단계·인용 생성(LLM, JSON) — 형식이 깨지면 한 번 다시 묻고, 그래도 안 되면 원문을 보인다.
6. 인용 검증 — 공백·대소문자를 정규화한 인용구가 원문에 있는지 부분 문자열로 대조. 다른 기록에 있으면 번호를 고쳐 통과.
7. 출처 조회 — 검색된 기록마다 어디서 왔는지 DB 에서 채운다(아래 4절).
8. 답변 표시 — 단계마다 verified · unverified, 기록이 다루지 않는 부분(missing), 근거가 없으면 기권.

## 4. 검색 색인과 출처 조회 — 정비 문서 기록과 참고 기록

`data/bm25_1000.pkl` 은 `tools/rebuild_index.py`(= `app/rag.py` 의 `build_index` · `index_rows`)가 DB 에서 만든다.

| 종류 | 출처 | 건수 | 색인 속 표지(meta) | 출처 표에 보이는 것 |
|---|---|---|---|---|
| 정비 문서 기록 | `master` 에서 서술(WORK_REMARK) 300자 이상 | 741 | (선박코드, 문서번호, 제목, 기기, 장비, 작업일, 본문) | master 의 선박 · 기기 코드·호기 · 장비 코드·호기 · 문서번호·작업일 · 담당 직책·부서, pms 의 정비 항목(주기·중요도) |
| 참고 기록 | `qa_proc_context`(절차형 100문항 × 고정 문맥 4건 = 400행), 본문이 같은 것은 하나로 | 305 | ('QA_REF', '<문항ID>-<기록번호>', 제목, 기기, 장비, 작업일, 본문) | qa_proc_context 의 제목 · 기기·호기 · 장비·호기 · 작업일 · 이 본문을 문맥으로 쓰는 문항ID 전부(예: P063-1 · P063-2 …) |

토큰화(영문 소문자·숫자, 불용어·두 글자 이하 제외) · 가중(제목 3배 + 본문 + 기기명 + 장비명) · 점수식(BM25, k1 1.5 · b 0.75)은
연구 시스템과 같다. 정비 문서 기록의 대상 조건(300자 이상)도 같다. 참고 기록을 함께 넣은 것은 학생판에서 더한 것이다 —
가명 DB 의 master 서술은 합성 문장이라 절차형 100문항의 근거가 없고, 실제 정비기록(가명처리)은 qa_proc_context 에만 있기 때문이다.
그래서 절차형 문항을 웹 화면에서 물으면 그 문항의 고정 문맥 기록이 검색되어 단계와 인용 검증이 나온다
(평가기는 검색하지 않고 문맥 4건을 그대로 넣는다 — 연구의 고정 문맥 시험).

참고 기록은 master 의 행이 아니어서 선박 · 담당 직책 · 정비 항목이 없다. 출처 표는 참고 기록 줄에 그 표의 열 이름으로 된
머리행(`Source · Machinery · Unit · Equipment · Unit · Date · Fixed context of`)을 따로 쓰고, 같은 본문을 쓰는 기록이 여럿이면
호기·날짜를 모두(예: MOORING WINCH 1–4), 문항ID 는 문항별로 묶어(예: `P063 · records 1–4`) 보인다. 정비 문서 기록 줄은
연구 시연판과 같고, 원문 머리에 `synthetic narrative`(가명 DB 의 master 서술은 합성 문장)라고 적는다. 표 아래 설명도 기록 종류
(정비 문서만 · 참고 기록만 · 둘 다)에 맞춰 바뀐다.

## 5. 후속 질문 · 병기 · 중단

- 후속 질문: 지시어가 있거나 8자 이하인 질문만 직전 3턴으로 완결된 질문으로 다시 쓴다(LLM). 대화 이력은 이 재작성에만 쓴다.
- 한국어 병기: 켰을 때만 질문·답을 한국어로도 만든다. 집계형 답 문장은 모델 없이 조립한다.
- 중단: 화면의 정지 버튼 → `/api/cancel` 이 LLM 연결을 닫아 실행기도 생성을 멈추게 한다. 응답을 기다리는 동안 0.5초마다 중단을 확인한다.

## 6. 배치와 실행

![배포와 실행](fig_deployment.png)

그림의 ①(원 DB → 가명처리 → 색인·사전)은 교수자 쪽에서 끝났다. 학생에게 가는 것은 zip 하나(이 패키지 · DB 엑셀 사본 · 읽어보기)다.
학생 PC 에서는 ③만 한다: 파이썬 · duckdb · LLM 실행기를 준비하고 `START.bat`. 모델 파일과 실행기는 패키지에 들어 있지 않다.

- `START.bat` → 파이썬 고르기(python → py -3 → python3) → `tools/check_llm.py --check-duckdb`(duckdb 1.5 이상 2 미만, 아니면
  `pip install -r requirements.txt`) → `--print-port`(설정 확인) → `--quick`(LLM 응답) → 이 폴더의 절대경로
  `<패키지>\app\maintqa_web.py --hide --log logs/maintqa_web.log` 로 기동 → `/api/info` 가 이 프로그램인지 확인되면 브라우저를 연다.
- `STOP.bat` 은 이 폴더의 서버만 끈다: ① `logs/web.pid`(기동 때 남긴 번호표)의 프로세스, ② 번호표로 끄지 못했을 때만 명령줄에
  이 폴더의 `app\maintqa_web.py` 절대경로가 든 파이썬. 다른 폴더의 사본 · LLM 실행기는 건드리지 않는다. 자체 점검(selftest)의
  임시 서버는 번호표를 임시 폴더에 써서(`--pid-file`) 실제 서버의 번호표를 덮어쓰지 않는다.
- 기동 때 검색 색인이 없으면 DB 에서 만든다. 첫 집계형 질문이 빠르도록 조건 F 프롬프트 앞부분을 한 번 예열한다(config 의 `warmup`).
- 안전장치: DB 읽기 전용 · 모델이 쓴 SQL 의 외부 파일·네트워크 접근 차단 · SQL 시간 제한 · 이 PC/사내망이 아닌 LLM 주소 거부
  (`allow_remote`) · 서버는 127.0.0.1 에서만 듣는다.
