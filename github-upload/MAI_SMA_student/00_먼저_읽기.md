# MAI SMA 학생 패키지 — 먼저 읽기

MAI SMA(Smart Maintenance Advisor)는 선박 정비이력에 대한 질문에 답하는 질의응답 시스템이다. 이 패키지 하나로
**자기 PC 의 로컬 LLM**(Ollama · LM Studio · llama.cpp 등)에 붙여 연구에서 쓴 웹 화면을 그대로 띄우고, 같은
200문항으로 모델을 평가할 수 있다. 데이터는 함께 든 **학생용 DuckDB(정비 문서 1,000건 + 질의응답 200문항)** 하나뿐이며,
질문과 기록은 PC 밖으로 나가지 않는다.

질문은 두 경로로 처리된다.

| 경로 | 이런 질문 | 하는 일 |
|---|---|---|
| 집계형(Text-to-SQL) | "주기관 정비를 호기별로 세어줘" | LLM 이 SQL 한 줄을 쓰고 → DuckDB 가 실행 → 수치는 DB 결과 그대로 |
| 기권 | "정비 한 건에 평균 몇 명이나 투입돼?" | 기록이 없거나 믿을 수 없는 값이면 SQL 대신 `NO_RELIABLE_VALUE` · `NOT_RECORDED` |
| 절차형(검색 + 인용) | "보일러 노 내화재에 실금이 보이는데 바로 보수해야 하나?" | 기록 4건 검색(BM25) → LLM 이 단계와 근거 인용 → 인용이 원문에 글자 그대로 있는지 검증 |

## 전체 흐름 — 각 단계의 성공 판정

| 단계 | 할 일 | 성공 판정 | 절 |
|---|---|---|---|
| 1 | 준비물 확인 | 파이썬 3.10 이상 · 로컬 LLM 실행기 하나 · 12B 급 모델 | 1 |
| 2 | 압축 풀기 · 꾸러미 설치 | `python -c "import duckdb; print(duckdb.__version__)"` 가 **1.5 이상 2 미만**(예: 1.5.3)을 찍는다 | 2 |
| 3 | LLM 실행기 켜기 | 브라우저에서 `…/v1/models` 주소가 모델 목록(JSON)을 보인다 | 3 |
| 4 | LLM 연결 설정(config.json) | `python tools/check_llm.py --quick` → `LLM 응답 확인 — …` | 4 |
| 5 | 자체 점검 | `python tools/selftest.py` 마지막 줄 `selftest PASS — …`(FAIL 0) · `python tools/check_llm.py` 판정 "진행해도 됩니다" | 5 |
| 6 | (사고형 모델일 때만) 사고 끄기 | check_llm 의 사고(thinking) 경고가 사라진다 | 6 |
| 7 | 웹 서버 켜기 | `START.bat` → 브라우저에 MAI SMA 화면, 왼쪽 아래 `1,046 records indexed · 741 documents + 305 reference` | 7 |
| 8 | 예시 질문 | 집계형은 SQL 과 표가 나오고, 기권은 노란 상자, 절차형은 verified 인용이 붙는다(값이 정답과 같은지는 모델 성능 — 8절) | 8 |
| 9 | 평가 | `python eval/run_eval.py --self-test` 마지막 줄 `self-test PASS` 뒤 `eval/eval_from_config.py` 로 채점 | 9 |

명령은 모두 **패키지 폴더(MAI_SMA_student)에서** 연다. 탐색기에서 이 폴더를 연 뒤 주소 표시줄에 `cmd` 를 치고
Enter 를 누르면 그 자리에서 명령 프롬프트가 열린다. 아래 예의 `python` 이 안 되면 `py -3` 으로 바꿔 친다
(START.bat 도 같은 순서 — `python` → `py -3` → `python3` — 로 파이썬을 고른다. 꾸러미를 설치한 파이썬과 서버를 띄우는
파이썬이 같아야 한다. START.bat 의 [1/5] 줄에 고른 파이썬의 경로가 찍힌다).

## 1. 준비물

- **PC**: Windows 10/11(START.bat · STOP.bat), 또는 macOS · Linux(`sh start.sh`).
- **파이썬 3.10 이상** — https://www.python.org/downloads/ . 설치 첫 화면에서 **Add python.exe to PATH** 를 반드시 체크한다.
- **로컬 LLM 실행기 하나** — Ollama(https://ollama.com), LM Studio(https://lmstudio.ai), llama.cpp 의 llama-server,
  또는 OpenAI 호환 API(`/v1/chat/completions`)를 여는 다른 서버(vLLM 등).
- **모델** — 12B~14B 급 지시 따르기 모델을 권한다. 연구에서 배포 기준(원출력 재현 · 기권 지시이행 · 인용 충실도)을 통과한 것은
  12B · 14B 급 두 모델이었다. 7B 이하는 기록이 없는 항목에도 숫자를 만들거나 JSON 형식을 자주 어긴다.
  4비트 양자화 12B 모델은 대략 GPU 메모리 8GB 이상 또는 시스템 메모리 16GB 이상이 있으면 돈다(CPU 만 쓰면 느리다).
- **문맥 길이 8,192 토큰 이상** — 집계형 프롬프트가 약 1만 4천 자(6~7천 토큰)다. 실행기 기본값이 이보다 작으면 늘린다(3절).
- 인터넷은 파이썬·꾸러미·실행기·모델을 처음 받을 때만 쓴다. 그 뒤로 이 시스템은 외부와 통신하지 않는다.

## 2. 압축 풀기와 파이썬 꾸러미 설치

1. `MAI_SMA_학생전달.zip` 을 마우스 오른쪽 → **압축 풀기**(Windows 탐색기). 안에 `읽어보기.txt` ·
   `MAI_SMA_학생용DB_1000.xlsx`(DB 둘러보기용 엑셀) · `MAI_SMA_student/`(이 패키지)가 있다.
   경로가 너무 깊지 않은 곳(예: `C:\MAI_SMA\` 또는 바탕화면)에 둔다.
2. 패키지 폴더에서 꾸러미를 설치한다.

   ```
   python -m pip install -r requirements.txt
   ```
   필수는 `duckdb` 하나다(**판 1.5 이상 2 미만** — requirements.txt 가 이 범위로 깐다). `psutil`(설정 창의 메모리 표시) ·
   `openpyxl`(엑셀 기록양식 채우기)은 선택이다: `python -m pip install psutil openpyxl`

**성공 판정**: `python -c "import duckdb; print(duckdb.__version__)"` 가 **1.5 이상 2 미만**의 판 번호(예: `1.5.3`)를 찍는다.
`python tools/check_llm.py --check-duckdb` 로도 확인할 수 있다(`duckdb … — 맞는 판입니다`).

**흔한 오류**
- duckdb 판이 범위 밖이다(2.0 이상, 또는 1.5 미만이 이미 깔려 있었다) → 아래 한 줄로 맞춘다. 2.x 에서는
  `Relations no longer have fetchone()`, 1.1~1.4 에서는 `Connection has already been closed` 같은 오류가 난다 —
  코드의 문제가 아니라 판의 문제다. 코드를 고치지 말고 판을 맞춘다.
  ```
  python -m pip install "duckdb>=1.5,<2"
  ```
- `'python'은(는) … 명령이 아닙니다` → 파이썬 설치 때 PATH 체크를 빠뜨렸다. `py -3` 으로 쳐 보거나 파이썬을 다시 설치하며 체크한다.
- `python` 을 치면 Microsoft Store 가 열린다 → 스토어의 '앱 실행 별칭'이다. 설정 → 앱 → 고급 앱 설정 → 앱 실행 별칭에서
  python.exe · python3.exe 를 끄거나, python.org 판을 설치한다.
- pip 가 SSL·프록시 오류로 멈춘다 → 학교·회사망의 프록시 문제다. 다른 망에서 설치하거나 담당자에게 프록시 주소를 받는다.
- 압축을 풀었는데 `data` 폴더의 파일 이름이 `MAI_SMA_???DB_1000.duckdb` 처럼 깨졌다 → 한글 파일 이름을 못 읽는 압축 프로그램이다.
  Windows 탐색기의 '압축 풀기'나 7-Zip 최신판으로 다시 푼다.

## 3. LLM 실행기 켜기와 모델 받기

실행기는 하나만 있으면 된다. 켠 뒤 브라우저로 아래 주소를 열어 모델 목록(JSON)이 보이면 준비된 것이다.

| 실행기 | 켜기 | 확인 주소 | 문맥 길이 8,192 이상으로 |
|---|---|---|---|
| Ollama | 시작 메뉴의 Ollama 앱(또는 `ollama serve`). 모델은 `ollama pull <모델>` (예: `gemma3:12b`, `qwen2.5:14b` — 이름은 Ollama 라이브러리에서 확인) | http://localhost:11434/v1/models | Ollama 앱 설정의 Context length 를 8k 이상, 또는 환경변수 `OLLAMA_CONTEXT_LENGTH=8192` 를 두고 Ollama 를 다시 켠다 |
| LM Studio | 모델을 내려받아 불러온 뒤 Developer(개발자) 화면에서 로컬 서버를 켠다(Status: Running) | http://localhost:1234/v1/models | 모델을 불러올 때 Context Length 를 8192 이상 |
| llama.cpp | `llama-server -m <모델.gguf> --port 8080 -c 8192 -np 1` | http://127.0.0.1:8080/v1/models | `-c 8192` 이상, `-np 1` 권장(슬롯이 여럿이면 문맥이 나뉜다) |
| 그 밖의 OpenAI 호환 서버 | 서버 안내대로 | `<주소>/v1/models` | 서버의 최대 문맥(`max_model_len` 등) 8192 이상 |

## 4. LLM 연결 설정 — config.json

패키지 폴더의 `config.json` 하나가 "어느 실행기의 어느 모델에 붙을지"를 정한다. `config_examples/` 에서 자기 실행기의
예시(`ollama.json` · `lmstudio.json` · `llamacpp.json` · `openai_compatible.json`)를 골라 패키지 폴더에 **config.json 으로
복사해 덮어쓴 뒤** 메모장으로 고친다.

```json
{
  "preset": "ollama",
  "base_url": "http://localhost:11434/v1",
  "model": "gemma3:12b",
  "context_tokens": 8192,
  "timeout_sec": 600,
  "web_port": 8780
}
```

| 이름 | 뜻 |
|---|---|
| `preset` | `ollama` · `lmstudio` · `llamacpp` · `openai` 중 하나. 실행기마다 받는 요청 필드가 달라 그에 맞춘다 |
| `base_url` | 실행기 주소. 끝은 `/v1` |
| `model` | 실행기에 있는 모델 이름 그대로(Ollama: `ollama list`, LM Studio: 모델의 API identifier). **llama.cpp 는 비워 둔다**(`""`) — llama-server 는 이 이름을 보지 않고, 화면에는 실행기가 알려 주는 모델 파일 이름이 나온다. 꼭 적으려면 파일 이름만(예: `gemma-4-12B-it-Q4_K_M.gguf`) 적는다. `/v1/models` 에 보이는 전체 경로를 그대로 붙이지 않는다(역슬래시 때문에 JSON 오류) |
| `api_key` | 보통 `""`. 로컬 실행기는 키가 필요 없다(키가 필요한 사내 서버만) |
| `context_tokens` | 실행기에 설정한 문맥 길이(8192 이상) |
| `timeout_sec` | LLM 한 번 호출을 기다리는 최대 초(기본 600). CPU 만 쓰는 느린 PC 에서 시간 초과가 나면 늘린다 |
| `web_port` | 웹 화면 포트(기본 8780). 다른 프로그램이 쓰면 바꾼다. 화면 주소는 `http://127.0.0.1:<web_port>/` |
| `warmup` | 기본 `true`. 서버를 켤 때 집계형 프롬프트 앞부분을 실행기에 한 번 미리 보내 첫 질문을 빠르게 한다 |
| `extra_body` | 요청에 덧붙일 필드(예: 사고 끄기, 6절). 보통 `{}` |
| `gguf_path` | (선택) 실행기가 쓰는 GGUF 모델 파일의 경로. 적으면 설정 창이 그 파일 헤더에서 모델 제원(층 수 · 양자화 · KV 캐시)을 읽는다. 비워도 된다 |
| `llama_server` | (선택, llama.cpp) 실행기가 꺼져 있을 때 이 프로그램이 llama-server 를 직접 띄우는 설정. `exe`(llama-server 실행 파일) · `model_path`(.gguf) 를 **둘 다** 채웠을 때만 쓴다. `ngl`(GPU 에 올릴 층 수, 기본 99) · `extra_args`(덧붙일 인자) |
| `allow_remote` | 기본 `false`. 이 PC·사내망이 아닌 주소는 막는다(정비기록이 밖으로 나가므로). 담당 교수의 허락 없이 바꾸지 않는다 |

**윈도 경로를 적을 때**(`gguf_path` · `llama_server` 의 `exe` · `model_path`): JSON 에서 역슬래시(`\`)는 특수 문자다.
**`/` 로 바꿔 적거나 `\\` 로 두 번** 적는다. 예:

```json
  "gguf_path": "C:/llama/models/gemma-4-12B-it-Q4_K_M.gguf",
  "llama_server": {
    "exe": "C:/llama/llama-server.exe",
    "model_path": "C:/llama/models/gemma-4-12B-it-Q4_K_M.gguf",
    "ngl": 99,
    "extra_args": ["--cache-reuse", "256", "-np", "1"]
  }
```

**성공 판정**: `python tools/check_llm.py --quick` → `LLM 응답 확인 — Ollama · http://localhost:11434/v1 · 모델 … · 모델 N개`

**흔한 오류**(`--quick` 의 종료 코드: 0 정상 · 10 설정 오류 · 11 주소 무응답 · 12 모델 없음 · 13 주소 무응답이지만
`llama_server` 설정이 있어 웹 서버가 llama-server 를 직접 띄운다 — START.bat 은 13 이면 그대로 진행한다)
- `model 이 아직 자리표시값입니다` → `"<<…>>"` 를 실제 모델 이름으로 바꾸지 않았다.
- `JSON 으로 읽지 못했습니다(줄 n, 칸 m)` → 쉼표·따옴표·중괄호를 확인한다. JSON 에는 주석(`//`, `#`)을 쓸 수 없다. 마지막 항목 뒤에는 쉼표가 없어야 한다.
- `JSON 으로 읽지 못했습니다(…): Invalid \escape` → 경로의 역슬래시를 그대로 적었다. 위 예처럼 `/` 로 바꾸거나 `\\` 로 적는다.
- `LLM 주소가 응답하지 않습니다` → 실행기가 꺼져 있거나 포트가 다르다(3절의 확인 주소를 브라우저로 열어 본다).
- `모델 "…" 이(가) 목록에 없습니다` → 목록에 찍힌 이름을 그대로 복사해 넣는다(Ollama 는 `:latest` 같은 태그까지).
- `base_url 이 이 PC 나 사내망 주소가 아닙니다` → 외부 API 주소를 적었다. 원칙은 로컬 실행기다.

## 5. 자체 점검 — selftest 와 check_llm

```
python tools/selftest.py
```
실제 LLM 없이(이 PC 안에 모의 LLM 을 잠깐 띄워) 패키지의 모든 경로를 끝까지 돌려 본다: DB 와 색인, 프롬프트가 연구와
글자까지 같은지, 웹 서버 기동과 /api 전부(집계형 · 기권 · 절차형 · 참고 기록 출처 · 후속 질문 · 병기 · 중단 · 오류),
터미널판, 평가기 자체 검사, 엑셀 기록양식. 1~3분 걸린다.

**성공 판정**: 마지막 줄이 `selftest PASS — 패키지가 제대로 놓였습니다. …` 이다(그 위 줄은 `결과: N/N PASS · …` 요약).
실패가 있으면 마지막 줄이 `selftest FAIL — 실패 n개 …` 이고 요약 줄에 `FAIL n` 이 붙는다 — 위쪽의 `[FAIL]` 줄을 본다.
`[참고]` 줄(config.json 을 아직 채우지 않았다 · openpyxl 이 없어 엑셀 점검을 건너뛰었다)은 실패가 아니다.
selftest 는 모의 LLM 과 임시 웹 서버(빈 포트)를 쓰므로, 이미 켜 둔 웹 서버(START.bat)나 그 번호표(logs\web.pid)를 건드리지 않는다.

그다음 실제 LLM 을 점검한다(LLM 을 다섯 번 부른다. 느린 PC 에서는 몇 분).
```
python tools/check_llm.py
```
짧은 대화 → 문맥 길이(긴 글의 맨 앞을 기억하는가) → 집계형 SQL → 기권 → 절차형 JSON·인용을 차례로 본다.
**성공 판정**: 마지막에 `판정(…초): 이 설정으로 웹 화면과 평가를 진행해도 됩니다.` 결과는 `logs/check_llm_report.txt` 에도 남는다.

**흔한 오류**
- selftest `[FAIL] 필수 파일` → 압축이 덜 풀렸거나 파일 이름이 깨졌다(2절).
- selftest `[FAIL] duckdb 설치` · `[FAIL] duckdb 1.5 이상 2 미만` → 2절의 꾸러미 설치를 다시 한다(`python -m pip install "duckdb>=1.5,<2"`).
- selftest `[FAIL] C 절 실행 — JSONDecodeError` → config.json 을 JSON 문법에 맞게 고친다(4절). 메모장의 "UTF-8(BOM)" 저장은 괜찮다.
- check_llm `4 문맥 길이 FAIL` → 실행기의 문맥 길이가 8192 보다 작아 프롬프트 앞이 잘린다. 3절대로 늘린다.
- check_llm `5 집계형 SQL` · `6 기권` 실패 → 모델이 작거나 지시를 따르지 못한다. 더 큰 모델을 쓴다(연구의 소형 모델 한계와 같다).
- check_llm `7 절차형 JSON 형식 실패` → 소형 모델에서 흔하다. 웹 화면은 한 번 다시 묻고, 그래도 안 되면 원문을 보여 준다.

## 6. 사고(thinking) 모델일 때

어떤 모델은 답 앞에 긴 생각(`<think>…</think>`)을 먼저 쓴다. 이 패키지는 그 덩어리를 걷어 내지만 시간이 그만큼 더 걸리고,
출력 한도를 생각에 다 써서 답이 비는 일도 생긴다(오류 문구: "모델이 사고(thinking)에 출력 한도를 다 써서 답이 비었습니다").
- llama.cpp(`preset: llamacpp`): 이 패키지가 요청마다 사고 끄기(`chat_template_kwargs: {"enable_thinking": false}`)를 보낸다.
- LM Studio: 모델 설정에서 Thinking(Reasoning) 표시를 끄거나 사고하지 않는 모델을 고른다.
- Ollama: 사고하지 않는 모델(태그)을 고른다. 실행기가 받는 사고 끄기 필드가 있으면 `extra_body` 에 넣는다.
- 그래도 안 되면 사고하지 않는 지시 따르기 모델로 바꾼다. **성공 판정**: check_llm 의 사고(thinking) 경고가 사라진다.

## 7. 웹 서버 켜기 — START.bat

`START.bat` 을 더블클릭한다(macOS·Linux: `sh start.sh`). 창이 다섯 단계를 확인한다:
`[1/5] 파이썬 확인(고른 파이썬의 경로) → [2/5] duckdb 확인(판 1.5 이상 2 미만, 아니면 requirements.txt 로 설치를 묻는다) →
[3/5] 설정 확인 → [4/5] LLM 응답 확인 → [5/5] 화면 서버 기동`.
준비되면 브라우저가 `http://127.0.0.1:<web_port>/`(기본 8780)을 열고 창은 닫힌다. 서버는 창 없이 뒤에서 돈다.
**끌 때는 `STOP.bat`**(macOS·Linux: `sh start.sh stop`). LLM 실행기는 그대로 둔다. STOP.bat 은 **그 폴더의 서버만** 끈다 —
기동 때 남긴 번호표(`logs\web.pid`)로 찾고, 번호표로 끄지 못했을 때만 명령줄에 이 폴더의 `app\maintqa_web.py` 절대경로가 든
파이썬을 찾는다(START.bat 이 그 경로로 띄운다). 같은 PC 에 패키지 사본이 여럿 있어도 다른 사본의 서버는 꺼지지 않는다.

**성공 판정**: 브라우저에 MAI SMA 화면이 뜨고, 왼쪽 위에 모델 이름, 왼쪽 아래에
`1,046 records indexed · 741 documents + 305 reference` 가 보인다. 첫 화면 카드 네 개(기권 · 집계 · 절차 · 판정 기준)가 있다.

**흔한 오류**
- "Windows 의 PC 보호" · "게시자를 확인할 수 없습니다" 창 → 인터넷에서 받은 파일에 붙는 경고다. '추가 정보 → 실행'.
- `[!] 8780 번 포트를 다른 프로그램이 쓰고 있습니다` → config.json 의 `web_port` 를 8781 등으로 바꾼다.
- `[!] 화면 서버가 시작되지 못했습니다` → 창에 `logs\maintqa_web.log` 의 마지막 부분이 나온다. 그 글로 원인을 본다.
- 브라우저가 열리지 않는다 → 직접 `http://127.0.0.1:8780/`(포트는 config.json 의 `web_port`)을 연다.
- 서버의 출력을 창에서 직접 보며 띄우고 싶다 → 명령 프롬프트에서 `python app/maintqa_web.py` (이 창에 기록이 찍히고 브라우저가
  열린다. 끌 때는 이 창에서 Ctrl+C). 터미널판은 `python app/maintqa_cli.py`.

## 8. 예시 질문 해 보기

왼쪽 'Suggested questions' 를 누르면 그 질문이 새 대화로 나간다. 목록과 기대 결과는 `data/demo_questions.txt` 에 있다
(줄 끝 `←` 뒤가 이 DB 의 정답, `[Q090]` 같은 꼬리표가 DB 의 문항ID).

**성공 판정(설치가 제대로 되었는가)**: 집계형은 SQL 과 표가 나오고, 기권 질문은 노란 상자가 나오고, 절차형은 단계에
`verified` 인용이 붙는다. **수치가 정답과 같은지는 모델 성능이다** — 연구에서 배포 기준을 통과한 12B 급 모델도 몇 문항은 틀린다
(`demo_questions.txt` 의 4번 · 5번 메모에 실제로 나온 흔한 오답을 적어 두었다). 값이 틀려도 설치 고장이 아니다.
temperature 0 · top_k 1 · seed 42 로 보내도, 같은 질문의 답이 실행기의 캐시 상태(방금 다른 질문을 했는가 등)에 따라 달라질 수 있다.

- **집계형**: 답 문장 → 표 → "How this was produced" 아래에 모델이 쓴 SQL. 정답과 맞대 보려면 DB 의
  `qa_aggregate` 에서 그 문항의 `answer_text` 를 본다(10절). 예: 1번 → 1호기 122 · 2호기 125. 틀렸으면 SQL 을 정답 SQL(`gold_sql`)과
  견주어 본다 — 어느 규칙(예: 규칙 7 "발전기 = pms.MACH_DESC 정확일치")을 놓쳤는지가 보인다.
- **기권**: 노란 상자에 사유와 함께 `NO_RELIABLE_VALUE` · `NOT_RECORDED`. SQL 을 실행하지 않는다.
- **절차형**: 단계마다 `verified`(인용이 원문에 글자 그대로 있음) 또는 `unverified`(원문에 없음 — 그대로 믿지 않는다).
  "Sources" 표에서 머리행이 `Source · … · Fixed context of` 인 줄은 **참고 기록**(DB 의 `qa_proc_context`, 절차형 100문항의 고정
  검색 문맥 — 실제 정비기록을 가명처리한 것)이며, 그 본문을 문맥으로 쓰는 문항이 `P063 · records 1–4` 처럼 문항별로 묶여 나온다.
  선박 코드(V01~V06)가 보이는 줄은 **정비 문서 기록**(`master`)이며, 그 서술은 가명 DB 의 **합성 문장**이다(원문 머리에
  `synthetic narrative` 로 표시 — verified 는 "답이 기록 글과 맞는다"는 뜻이지 실제 정비 보고라는 뜻이 아니다). 원문 속 인용 구절은 형광으로 표시된다.
- **후속 질문**: 1번을 물은 뒤 같은 대화에서 `그럼 발전기는?` → 직전 질문을 이어 받아 "발전기 정비는 호기별로 세어줘" 같은 완결된
  질문으로 다시 써서(문장은 모델마다 조금 다르다) 답한다. 답 위에 `Continuing the previous turn, this was read as …` 로 다시 쓴
  질문이 보인다. 정답은 1호기 63 · 2호기 62 · 3호기 69(Q089).
- **한국어 병기**: 위쪽 "Korean alongside" 를 켜면 답을 한국어로도 보인다(생성이 길어져 느려진다).
- **설정 창**(톱니바퀴): 모델·실행기·요청 필드·문맥 길이·메모리·DB·색인 구성·데이터 사전.
- 답이 정답과 다르면 그것이 그 모델의 결과다. 프롬프트를 고치지 말고 9절의 평가로 기록한다.

## 9. 평가 — eval/

`eval/` 은 200문항(집계형 100 · 절차형 100)을 같은 규칙으로 채점하는 평가 세트다. 정답은 모두 이 DB(1,000건) 기준이다.
자세한 것은 `eval/00_평가_안내.md`.

```
python eval/run_eval.py --self-test                               채점기 자체 검사(LLM 호출 없음) → 마지막 줄 self-test PASS
python eval/eval_from_config.py --task agg --ids Q001-Q010        config.json 의 LLM 으로 집계형 10문항
python eval/eval_from_config.py --task proc --ids P001-P005       절차형 5문항(고정 문맥 4건 · 영어 질문)
python eval/fill_record_form.py eval/results/<결과>.csv           결과를 엑셀 기록양식 사본에 옮겨 적기
```
결과는 `eval/results/` 에 쌓인다(CSV · JSONL · 요약). 집계형은 O(정답) · X(오답) · E(실행 오류), 절차형은 "인용정확 k/n".
`fill_record_form.py` 는 원본 `eval/기록양식_200문항.xlsx` 를 건드리지 않고, 그 사본 `eval/results/기록양식_<모델>_<날짜>.xlsx` 의
⑥ 시트에 결과를 채운다(openpyxl 필요). 결과의 모델명은 config.json 의 `model` 이고(비웠으면 `(로컬)`), 버전 칸에는 실행기가
돌려준 모델 id 의 파일 이름만 적힌다(경로는 남기지 않는다). 기록양식 사본의 `<모델>` 자리도 모델명이 없으면 그 파일 이름을 쓴다.
평가를 돌린 뒤에도 `selftest` · `run_eval.py --self-test` 는 그대로 통과한다(학생이 만든 `eval/results/` 는 배포 점검에서 뺀다).
ChatGPT 같은 웹 서비스와 비교할 때는 `eval/prompts/F_nl/Q001.txt`(집계형) · `eval/prompts/P_en/P001.txt`(절차형)를 붙여넣고,
답을 엑셀 ⑥ 시트에 붙인 뒤 `python eval/run_eval.py --score-file eval/기록양식_200문항.xlsx` 로 채점한다.
**외부 서비스에 보내기 전에 담당 교수의 허락을 받는다**(절차형 문맥은 실제 정비기록 원문을 가명처리한 것이다).

## 10. DB 들여다보기 — 엑셀 · DuckDB

**엑셀**: zip 맨 위의 `MAI_SMA_학생용DB_1000.xlsx` 가 DB 와 같은 내용이다(시트 = 테이블). 긴 본문은 칸을 고른 뒤 수식 입력줄을 넓혀 본다.

| 테이블 | 행 | 내용 |
|---|---|---|
| `_readme` | 10 | 테이블 설명 |
| `master` | 1,000 | 정비 문서 1건 = 1행. 키 (VESSELCODE, DOC_NO). `WORK_REMARK` 가 정비 서술 |
| `pms` | 2,296 | 정비 작업 라인. master 와 (VESSELCODE, DOC_NO) 로 잇는다 |
| `approval` · `attachments` · `consumption` | 2,979 · 286 · 174 | 결재 단계 · 첨부 파일 · 부품 소모 |
| `vessels` | 6 | 선박 6척(V01~V06 · VESSEL-A~F). 집계 열은 이 DB 기준 |
| `qa_aggregate` | 100 | 집계형 문항: 질문 4문형 · 정답 SQL · **이 DB 기준 정답**(`answer_text` · `answer_json`, 빈 값은 키트와 같이 `NULL`) · 함정 SQL · `trap_kept` · `full_db_answer_json`(전체 선대 기준, 참고) |
| `qa_procedural` | 100 | 절차형 문항: 질문(`question_ko` · `question_en` = 평가 프롬프트와 웹 예시에 쓰는 원 문안) · 기대 답변 · 근거 인용 · `keep` · `keep_status` · `final_question_ko` · `final_question_en`(검수 때 고친 문안 — 7문항만, 참고) |
| `qa_proc_context` | 400 | 절차형 문항마다 모델에 주는 고정 검색 문맥(기록 4건). 웹 화면 검색 색인의 '참고 기록' |
| `prompt_templates` | 5 | LLM 에 보내는 프롬프트 원문(조건 A · C · F, 절차형 답변)과 데이터 사전 |

`qa_procedural.keep` 은 세 가지다: `true` 57문항(채택) · `false` 12문항(감사 경고 — 기대 답변 일부가 기록 근거와 다르다는 지적을
받은 문항, 참고 답안으로만) · 빈 값(NULL) 31문항(미판정 — 검수 기록이 없다. P031~P060 · P098). `keep_status` 칸에 같은 뜻을
글(채택 · 감사 경고 · 미판정)로 적었다. 채점은 keep 과 무관하게 인용 대조만 한다. `final_question_ko` · `final_question_en` 은
검수 때 고친 문안으로 7문항(P008 · P009 · P010 · P013 · P015 · P023 · P029)에만 있고, 프롬프트에는 쓰지 않는다.

**DuckDB(파이썬)**: 패키지 폴더에서 `python` 을 띄운 뒤

```python
import duckdb
con = duckdb.connect('data/MAI_SMA_학생용DB_1000.duckdb', read_only=True)
print(con.sql("SELECT * FROM _readme"))
print(con.sql("SELECT qid, question_nl, answer_text, trap_kept FROM qa_aggregate WHERE qid = 'Q090'"))
print(con.sql("SELECT qid, kind, question_ko, expected_answer FROM qa_procedural WHERE keep LIMIT 5"))
print(con.sql("SELECT qid, rec_no, title, machine, work_date FROM qa_proc_context WHERE qid = 'P063'"))
print(con.sql("SELECT MACH_NO, count(*) AS n FROM pms WHERE MACH_DESC = 'MAIN ENGINE(DIESEL)' GROUP BY 1 ORDER BY 1"))
```
DuckDB 명령줄 도구(https://duckdb.org)가 있으면 `duckdb -readonly data/MAI_SMA_학생용DB_1000.duckdb` 뒤 `.tables` · `SELECT …`.
DBeaver 같은 DB 도구로 열어도 된다. **늘 읽기 전용으로 연다.** DB 를 고치면 평가 정답(채점할 때 정답 SQL 을 이 DB 에서
다시 실행한다)과 `qa_aggregate` 의 적힌 정답이 어긋나고, 검색 색인도 다시 만들어야 한다(`python tools/rebuild_index.py`).
`eval/db/` 에 같은 DB 사본이 있다(평가 폴더만 떼어 써도 되게).

## 11. 이 DB 에 대해 꼭 알아 둘 것

- **1,000건 표본이다.** 비식별 키트 DB(6개 테이블 약 17만 행)에서 정비 문서 1,000건을 뽑았다. 규칙의 함정이 살아 있도록
  문서번호가 여러 배에 겹치는 문서 · 소모 기록 · 발전기 · 주기관 · 중요 정비 · 첨부 · 긴 서술을 먼저 넣고 나머지는 선박별로
  고르게 채웠다(난수 씨앗 고정). 만든 방법은 `build/build_student_db_1000.py`.
- **정답은 이 DB 기준이다.** `qa_aggregate.answer_text` · `answer_json` 과 `eval/` 의 정답은 같은 값이다. `full_db_answer_json` 은
  전체 선대 기준 참고값이라 이 DB 에서 SQL 을 돌린 결과와 다르다(채점에 쓰지 않는다).
- **함정이 사라진 문항이 있다.** `trap_kept = false` 인 3문항(Q060 · Q063 · Q078)은 표본에서는 규칙을 모르는 naive SQL 도 같은 답을 낸다.
- **프롬프트 규칙문의 통계는 전체 선대 기준이다.** 조건 F 프롬프트의 "소요시간의 73% 가 1.0", "consumption 은 전체 문서의 3.21%",
  "CRITICAL_YN Y 10,752 / N 40,963", "CONS_YN 플래그 43건 어긋남", "상관 0.16" 같은 수치는 17만 행 전체에서 잰 값이다. 이 DB 에서
  세면 다르다(예: 소모 기록이 있는 문서 7.5%, CRITICAL_YN Y 712 / N 1,584). 연구와 같은 조건으로 비교하려고 **프롬프트는 실험 그대로 두었다.**
  규칙문은 "어떻게 질의할지"를 알려 주는 것이고, 답의 수치는 늘 이 DB 를 실행한 결과다.
- **데이터 사전의 개수·분포도 전체 선대 기준이다.** `data/datadict_deid.txt`(= 조건 F 프롬프트의 컬럼 설명)에 적힌 "MACH_CODE 179종",
  "EQUIP_CODE 293종 · 2.2% 결측", "DEPT E=13,823 / D=12,728", "PIC 1등기관사 8,083 …", "PMS_TYPE CA 43,385 …" 같은 수치는 17만 행에서
  잰 값이다. 이 DB 에서는 master 의 MACH_CODE 120종(pms 117종) · EQUIP_CODE 181종 · 2.8% 결측 · DEPT E 550 / D 448 / 빈칸 2 ·
  PMS_TYPE CA 1,864 / RH 400 / CM 32 다. 사전은 컬럼의 **뜻과 쓰는 법**을 알려 주는 것으로 읽고, 개수는 이 DB 에서 직접 센다.
- **검색 색인에는 두 종류의 기록이 있다**(`data/bm25_1000.pkl`, 1,046건).
  ① 정비 문서 기록 741건 — `master` 에서 서술 300자 이상(연구 시스템과 같은 조건·토큰화). 가명 DB 의 제목·서술은 합성 문장이다.
  ② 참고 기록 305건 — `qa_proc_context` 400건에서 본문이 같은 것을 하나로 합친 것. 실제 정비기록 원문을 가명처리한 것이라
  절차형 100문항을 웹 화면에서 물으면 이 기록을 찾아 단계와 인용 검증이 나온다. `master` 의 행이 아니어서 선박 · 담당 직책 ·
  정비 항목은 없고, 출처 표에는 제목 · 기기 · 장비 · 날짜 · 문항ID 가 나온다.
- **가명처리이지 익명화가 아니다.** 코드(선박 V01~V06 · VESSEL-A~F, 기기·장비 16자리 = 기기 5 + 호기 3 + 장비 5 + 호기 3)와
  제조사·모델(master 의 MAKER-nnn · TYPE-nnn, 서술 속 BRAND-nn · MODEL-nn) · 지명 · 서식번호(PLACE-nn · FORM-nn …)는 바꿨지만
  설명·날짜·수치는 남아 있다. **수업 밖으로 재배포하지 않는다.**

## 12. 문제 해결

| 증상 | 원인 · 조치 |
|---|---|
| 첫 집계형 질문이 1분 넘게 걸린다 | 처음에는 프롬프트 전체(약 7천 토큰)를 계산한다. 기동 직후 예열이 끝나면 빨라진다. CPU 만 쓰면 더 느리다 |
| 화면에 `LLM 서버에 연결하지 못했습니다` | 실행기가 꺼졌다. 실행기를 켜고 같은 질문을 다시 보낸다 |
| `프롬프트가 실행기의 문맥 길이보다 깁니다` | 3절대로 문맥 길이를 8192 이상으로 |
| `모델이 빈 답을 돌려주었습니다` · 사고 관련 문구 | 6절 |
| 절차형이 `Could not read the output format` | 모델이 JSON 을 못 지켰다. 한 번 다시 묻는다. 자주 나면 더 큰 모델 |
| 절차형 인용이 모두 `unverified` | 모델이 원문을 바꿔 적었다(요약·번역). 그 답은 쓰지 않는다 — 시스템이 걸러낸 것이다 |
| `SQL 실행 시간 초과(60초)` | 모델이 너무 무거운 SQL 을 썼다. config.json 의 `sql_timeout_sec` 로 조정할 수 있다 |
| 검색 색인을 다시 만들고 싶다 | `python tools/rebuild_index.py`(`--check` 는 같은지만 본다) |
| `Relations no longer have fetchone()` · `Connection has already been closed` | duckdb 판이 맞지 않는다(2.x 또는 1.4 이하). `python -m pip install "duckdb>=1.5,<2"` 뒤 다시 실행. 코드를 고치지 않는다 |
| 서버가 꺼지지 않는다 | `STOP.bat` 을 한 번 더. STOP.bat 은 이 폴더의 서버만 찾으므로, 명령 프롬프트에서 `python app/maintqa_web.py` 로 직접 띄운 서버는 그 창에서 Ctrl+C 로 끈다. 그래도 남으면 작업 관리자의 세부 정보에서 명령줄에 이 폴더의 `maintqa_web.py` 가 든 `python` 을 끝낸다 |
| 다른 PC 로 옮겼다 | 폴더째 복사하면 된다(절대경로를 쓰지 않는다). config.json 의 주소·모델만 그 PC 에 맞춘다 |

AI 도우미(ChatGPT · Claude · Copilot 등)에게 도움을 받을 때는 `AI_이식_프롬프트.md` 의 지시문을 먼저 붙여 넣는다.
오류를 물을 때는 오류 문구와 `logs/` 의 기록만 보이고, DB 의 정비기록 본문은 붙여 넣지 않는다.
